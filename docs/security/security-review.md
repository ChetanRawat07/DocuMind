# Security review (Phase 13)

A deliberate pass over the whole application: what each risk area relies on, where that is in the
code, and what risk remains. This is a self-review of a demo project, not an audit or a
certification.

**Method:**

- An independent code review, which read every controller, guard, repository, storage adapter,
  the text-extraction, AI and prompt code, and the web client. It found 2 issues, both fixed below.
- Checks of configuration, dependencies and git history.
- Automated tests for each new control. Each control was then broken on purpose to confirm a test
  fails (19 of 19 caught).
- Browser and database checks:
  - The web build was loaded in headless Chrome, which enforced its CSP.
  - The quota query plan was measured on 100,000 audit rows.
  - The visibility check was run on the dev database's real documents.

## Findings

| #   | Severity | Finding                                                                                                                                                                                                                                                         | Resolution                                                                                                                                   |
| --- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | MEDIUM   | A PDF text layer can hold text that is never drawn (invisible render mode, white on white, off page). Values grounded only in it could reach the 0.90 threshold and complete without review, e.g. an invoice showing 1,200.00 with a hidden total of 12,000.00. | Fixed: text-layer evidence must also be found by OCR on the rendered page, else `evidence_not_visible` sends it to review. Real-PDF test.    |
| 2   | LOW      | `GET /audit-logs?cursor=9999999999999999999` passed validation and failed in PostgreSQL (bigint out of range): a 500 and an error log per request. Nothing leaked.                                                                                              | Fixed: the schema rejects values above the bigint maximum (400).                                                                             |
| 3   | MEDIUM   | No rate limits or quota (known gap since Phase 2): one account could exhaust the AI budget or API memory.                                                                                                                                                       | Fixed: limits and quota above.                                                                                                               |
| 4   | MEDIUM   | No way to erase a user's data (known gap since Phase 2).                                                                                                                                                                                                        | Fixed: `DELETE /me` (ADR-010). The Supabase account is kept.                                                                                 |
| 5   | MEDIUM   | No CSP for the web app while the token is in `localStorage` (known gap since Phase 2).                                                                                                                                                                          | Partly fixed: meta-tag CSP. `frame-ancestors` and HSTS need host headers (Phase 16).                                                         |
| 6   | LOW      | Dev-only dependencies: 13 moderate advisories (ESLint's `minimatch`, ReDoS on crafted glob patterns). Production dependencies: 0.                                                                                                                               | Accepted: the patterns are our own lint configuration, not input. `npm audit fix` would downgrade the toolchain. Re-check on ESLint updates. |

## Rate limits and quota

| Limit               | Value                   | Scope                    | Store                | Answer             |
| ------------------- | ----------------------- | ------------------------ | -------------------- | ------------------ |
| Requests            | 300 per minute          | User, all routes         | Process memory       | 429, `Retry-After` |
| Processing requests | 10 per minute           | User, upload + reprocess | Process memory       | 429, `Retry-After` |
| Processing quota    | 50 per rolling 24 hours | User, upload + reprocess | PostgreSQL audit log | 429                |

- **Keyed by user id, not IP.** Behind the host's proxy every client shares one address, and
  trusting `X-Forwarded-For` blindly would let a client choose its own key.
- **After authentication.** A request without a valid token is rejected (401) before it counts.
- **Counted from the audit log.** Deleting documents or erasing data does not give the quota back.
  A repeated request for an already queued document is answered without using the quota.
- **Exact under concurrency.** The quota check locks the user row (`FOR NO KEY UPDATE`), which
  serializes the user's own requests without blocking review writes.
